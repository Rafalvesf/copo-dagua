# Profile (partner-app) — Casos Limite

- Parceiro edita um campo crítico (nome/NIF/categorias) enquanto o perfil já está `pending_review` de uma submissão anterior → não duplica revisão; apenas atualiza os dados, `submitted_at` mantém-se o da submissão original (evita reiniciar a fila de revisão a cada micro-edição).
- Parceiro remove todas as fotos de portefólio de um perfil já `published` (ex: limpa tudo antes de recarregar novo material) → perfil fica temporariamente abaixo do mínimo de RN04, mas **não** é despublicado automaticamente — RN04 só bloqueia a *submissão*, não retroage sobre perfis já aprovados. Documentar isto explicitamente na UI para não confundir o parceiro.
- Dois pedidos de submissão quase simultâneos (duplo tap em "Submeter") → `submit-partner-profile-for-review` deve ser idempotente; segunda chamada com `status` já `pending_review` devolve sucesso sem efeito, não erro.
- NIF que passa o checksum mas já está registado por outra conta (RN05) → mensagem distingue claramente "NIF inválido" de "NIF já registado" (dois erros diferentes, ver `validations.md`), o segundo caso pode indicar fraude e deve ficar sinalizado para o admin em `admin-web/partners/` (fora de âmbito, mas o dado tem de estar disponível para essa vista futura).
- Parceiro rejeitado tenta re-submeter sem alterar nada → permitido (a decisão de qualidade é do admin), mas o wizard mostra um aviso "Não fizeste alterações desde a rejeição — tens a certeza?".
- Conta do parceiro é suspensa a nível de `profiles.status` (Authentication, RN08 lá) enquanto o perfil está `published` → `is_partner_profile_visible()` já cobre isto (verifica `profiles.status = 'active'`), perfil desaparece do Marketplace sem precisar de mudar `partner_profiles.status` — os dois estados ficam dessincronizados de propósito (a conta pode ser reativada sem perder o histórico de aprovação do perfil).
- Categoria é desativada pelo admin (`partner_categories.is_active = false`) depois de parceiros já a terem selecionado → linhas existentes em `partner_profile_categories` não são apagadas (perfis já aprovados mantêm-se válidos); apenas deixa de aparecer como opção para novas seleções. Nunca fazer hard-delete de uma categoria com parceiros associados.
- Upload de portefólio falha a meio (rede cai depois do upload para Storage mas antes do insert em `partner_portfolio_items`) → ficheiro órfão no bucket sem linha correspondente; aceite como limitação do MVP, requer job de limpeza periódico (ver `tasks.md`), não bloqueia o utilizador.
- Parceiro tenta pausar (`is_paused = true`) um perfil que ainda está em `draft` ou `pending_review` → ação sem efeito visível (RN10 só se aplica quando `published`), mas o valor pode ser gravado sem erro para simplificar a UI (não precisa de bloquear o toggle antes de saber o estado).
- Preço "a partir de" preenchido para uma categoria que é removida a seguir no mesmo ecrã → o valor órfão em `pricesByCategory` (estado local) é descartado ao gravar; a tabela `partner_profile_categories` é a fonte de verdade, não o formulário.
